# Skill: Проверка скорости DNS

Используй, когда владелец спрашивает про скорость/качество DNS, жалуется
на медленный интернет/резолвинг, или когда в логах много строк
"curl error ... dns-query Failed to connect" (деградация DoH-резолверов).

## Как запросить свежий бенчмарк (СТРОГО в два хода)

Бенчмарк идёт ~20 секунд вне тебя, поэтому за один ответ его не получить.

ХОД 1 (владелец просит проверить DNS):
- Создай инструментом write_file файл `requests/dnsbench.req`
  (содержимое любое, например "run"). Это триггер для демона.
- НЕ читай `results/dnsbench.txt` на этом ходу — там будет старое.
- Ответь владельцу коротко: «Запускаю бенчмарк DNS, ~20 секунд.
  Спроси "покажи скорость DNS" через полминуты». И всё, больше ничего.

ХОД 2 (владелец спрашивает результат):
- Прочитай `results/dnsbench.txt`, смотри ПЕРВУЮ строку:
  - "# RUNNING ..." — ещё не готово, попроси подождать ещё ~15 секунд.
  - "# Бенчмарк DNS — <время>" — готово, разбирай и показывай.

## Формат результата

Сверху — блок «Настроены сейчас на роутере» (реальный конфиг из RCI).
Таблица: Сервер | прот(dot/doh) | конф | усп% | ср.мс, где:
- конф = "+" — резолвер СЕЙЧАС используется роутером; "-" — резерв
  (меряется для сравнения, но в работе не участвует).
- усп% < 100 — резолвер частично недоступен.
- ср.мс — средняя задержка, меньше = лучше.

Давай КОНКРЕТНЫЕ рекомендации на основе колонки "конф" — не гадай
«если у тебя настроен...», ты это ЗНАЕШЬ из таблицы:
- Если какой-то из настроенных (+) заметно медленнее, чем доступный
  резерв (-) со 100% успехом — прямо предложи замену:
  «сейчас работает X (+, N мс), но резервный Y (-, M мс) быстрее».
- Если у настроенного (+) усп% < 100 — это проблема, укажи явно.
- Отметь, что физически переключить конфиг ты пока не можешь (это будет
  в следующей фазе), но можешь подсказать, что и на что менять.

## ПОЛИТИКА ПРИВАТНОСТИ РЕЗОЛВЕРОВ (правило владельца, нерушимое)

Резолвер видит все посещаемые домены, поэтому выбор — вопрос приватности:
- Приоритет 1 (можно рекомендовать свободно): Cloudflare, Quad9, Google,
  AdGuard, Mullvad — вне досягаемости РКН.
- Последняя очередь: Yandex DNS. Он взаимодействует с Роскомнадзором и
  может профилировать пользователей. НИКОГДА не рекомендуй Yandex как
  замену по скорости. Упоминать его как вариант можно ТОЛЬКО если ВСЕ
  резолверы приоритета 1 деградировали (усп% < 100 или задержки в разы
  выше обычного) — и то с явной оговоркой о приватности.
- Быстрота Yandex в таблице — это НЕ повод его включать. Так и объясняй,
  если владелец спросит, почему не Yandex: «быстрый, но видит все ваши
  домены и связан с РКН — политика: только последняя очередь».
- Планируемое исключение (согласовано, ещё не реализовано): split-DNS —
  Yandex постоянным резолвером СТРОГО для зон юрисдикции РФ (.ru, .рф, .su),
  напрямую; остальные зоны — только приоритет 1. Включится после прототипа,
  доказавшего отсутствие утечки других зон в Yandex при отказах резолверов.

## Как показать (через навык tg-rich, файл в outbox/)

Таблицу владелец читает с ТЕЛЕФОНА — она должна влезать без горизонтальной
прокрутки. Поэтому РОВНО 3 узкие колонки:

| Резолвер | Конф | мс |
| --- | --- | --- |
| Cloudflare DoT | + | 8 |
| Yandex DoT | - | 14 |
| ... | | |

Правила компактности:
- Протокол (DoT/DoH) пиши прямо в колонке «Резолвер», отдельной колонки нет.
- Колонку «усп%» в таблицу НЕ добавляй. Если у кого-то усп% < 100 —
  напиши это отдельной строкой под таблицей (обычно у всех 100%).
- Сортируй по «мс» (быстрые сверху).
- Блок «Настроено сейчас» и «Выводы» — обычным текстом до/после таблицы.
- НЕ вставляй таблицу палочками в обычный ответ — только через outbox.

## Ограничения

- Я только ЗАПУСКАЮ бенчмарк и читаю результат. Менять DNS-настройки
  роутера я не могу (это следующая фаза). Могу подсказать, какой резолвер
  выбрать, и как переключить вручную.
- Не создавай запрос без повода (бенчмарк — это ~150 внешних запросов).
