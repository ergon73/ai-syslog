# Skill: Нагрузка роутера и сравнение с нормой

Используй, когда владелец спрашивает про нагрузку, производительность,
«всё ли в норме», тормозит ли роутер, CPU/память/соединения/скорость.

## Данные

1. `state/metrics.now` — ТЕКУЩИЕ метрики (обновляются каждые 5 минут):
   - cpu_pct — загрузка CPU, %
   - mem_pct — занятая RAM, %
   - conn_active — активные соединения (NAT-сессии); базовая метрика роутера
   - loadavg1 — load average ×100 (напр. 118 = 1.18)
   - wan_kbps — скорость на аплинке, КиБ/с
   В шапке файла — «слот часа: N» (час суток 0-23).

2. `state/baseline.tsv` — НОРМА по часам суток. Строки:
   METRIC<TAB>SLOT<TAB>N<TAB>MEAN<TAB>MAD
   (METRIC: cpu mem conn load wan; SLOT: час 0-23; MEAN — типичное значение,
   MAD — типичный разброс, N — сколько раз обновлялась норма этого часа).

## Как отвечать

- Возьми слот часа из шапки metrics.now, найди в baseline.tsv строки
  этого слота и сопоставь каждую текущую метрику с её нормой.
- Формулируй как «X сейчас Y при норме ~MEAN±MAD для этого часа»:
  - в пределах ±MAD (или чуть больше) — НОРМА;
  - сильно выше/ниже (в разы или > 3-4×MAD) — отклонение, укажи явно
    и предположи причину (много соединений → торрент/скан; высокий CPU
    → нагрузка/обновление; wan≈0 в активный час → возможен обрыв).
- Если для слота N < 5 — норма ещё копится (базлайн прогревается ~сутки
  на каждый час), честно скажи: «типичная нагрузка для этого часа ещё
  набирается, пока сравнивать не с чем — текущие значения такие-то».
- Ключевой смысл: абсолютное число само по себе мало значит; ценно
  ОТКЛОНЕНИЕ от типичного для этого времени.

## Ограничения

- Только читаю метрики и норму, ничего не запускаю и не меняю.
- Норма привязана к часу суток (нагрузка ночью и вечером разная).
