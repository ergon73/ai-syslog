# Eval-набор агента: эксплуатационные вопросы с проверкой по первоисточнику

Регрессионный набор для picoclaw-агента на роутере. Методика: эталонный ответ
вычисляется НЕЗАВИСИМО (awk по router.log, RCI, файлы state/), затем вопрос
задаётся агенту через CLI (`picoclaw agent -m "..."`) с чистой сессией
(sessions/* → archive/ перед прогоном; иначе агент подражает своей истории).
Прогонять после существенных изменений промптов/скиллов/инструментов.

## Найденные и исправленные дефекты (прогон №1)

1. **Внутренние часы агента в UTC** (−3ч во всех «сейчас») → S99picoclaw
   экспортирует TZ=Europe/Moscow + ZONEINFO=/opt/share/zoneinfo (пакет
   zoneinfo-europe); Go без zoneinfo игнорирует TZ.
2. **«Когда перезагружался» — не знал** → metrics-collect пишет boot_time
   (готовое MSK-время из /proc/uptime) в metrics.now; SOUL направляет туда.
3. **Относительные пути state/** в SOUL/load-check вели в workspace →
   заменены на абсолютные /opt/etc/observer/state/....
4. **Счёт при >200 совпадений невозможен** → loggrep пишет в шапку
   «ВСЕГО СОВПАДЕНИЙ: N»; скилл велит брать число оттуда.

## Дефекты, исправленные до eval (история)

- epoch-арифметика LLM (±3ч, не те даты) → loggrep отдаёт готовое время;
- чтение лога кусками = дыры 64КБ → запрет + loggrep;
- скиллы без frontmatter не обнаруживались → YAML name/description;
- сессия-самоподражание → сброс сессий при тестах, маршрутизация в SOUL;
- «за сутки» = только с 08:00 → правило day.acc + day.acc.prev.
